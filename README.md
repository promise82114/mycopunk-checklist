# Mycopunk 簡明攻略 Wiki

以裝備介紹、效果與取得條件為主的簡明攻略 Wiki；英文為主、繁體中文輔助。收集 checklist 是獨立輔助工具。採純靜態 HTML／CSS／ES modules，不需前端套件、帳號或資料庫。

線上網站：[Mycopunk Field Guide](https://promise82114.github.io/mycopunk-checklist/)

## GitHub Pages 部署

推送至 `main` 後，`.github/workflows/pages.yml` 會檢查 JavaScript、圖鑑與推薦資料，確認各匯入器可以離線重現提交內容，再發布 `prototype/`。也可在 GitHub Actions 手動執行 `Deploy GitHub Pages`。

Pages 的發布來源使用 **GitHub Actions**。網站發布內容僅包含 `prototype/`，Excel、翻譯來源與匯入腳本留在 repo 供重建，不會放入網站部署包。

發布前可執行 `npm run check`。本機與線上網站的瀏覽器儲存空間各自獨立，需要移轉收集紀錄時，請先匯出備份，再至線上網站匯入。

## 本機啟動

需要 Node.js 18 以上。在 repo 根目錄執行：

```powershell
node scripts/serve.mjs
```

開啟 [本機網站](http://127.0.0.1:18423/)。也可執行 `npm start`。請透過 HTTP 伺服器使用，不要直接雙擊 HTML；以 `Ctrl+C` 停止伺服器。

如連接埠被占用，可在 PowerShell 指定另一個：

```powershell
$env:PORT = '18425'
node scripts/serve.mjs
```

網站內容位於 `prototype/`，可由一般靜態 HTTP 伺服器供應；所有資源均在本機，沒有外部字型、翻譯 API 或追蹤服務。

- 裝備卡片與介紹頁使用 27 張個別簡化 SVG，以角色面罩、武器結構及主色區分；投擲物以元素／功能符號辨識，首頁仍保留四分類符號。參考公開 Wiki 圖像後以程式碼重繪，未下載來源圖片；非精確模型或皮膚預覽，適用外觀版本未註明。來源與特徵記錄見 [裝備圖示說明](research/equipment-art.md)，圖示依 CC BY-SA 4.0 提供。

### 三欄配裝工作區（2026-10-24）

- 設定區以四分類按鈕及目前分類的裝備按鈕攤開，無下拉選單；分類會記住本次最後使用的裝備。基礎面板依來源四階直接點選，重武器只提供固定 5×5；旋轉獨立選最高解鎖品質，另留未解鎖狀態。進入工作區後可收合設定。
- 左欄依品質由高到低列出「縮圖／中英名稱／小型格形／加入鈕」；缺少已收錄縮圖者用佔位符，不猜圖或新增下載。可搜尋、按品質篩選或只看已收集。多份配件逐份加入，保留原有模式限制。
- 中欄逐份編號並直接對照右欄。可用拖曳把手（Pointer Events、支援觸控）、原生列拖放或上下箭頭排序；每份穩定 ID、擴格屬性與選擇保留。點面板編號可定位中欄項目。
- 右欄縮為分布參考圖，使用配件品質色而非隨機配色。未裝入項目保留原因；擴格方向改在中欄逐份點選，面板仍顯示實際尺寸及合法安裝順序。
- 配件清單越前面越優先：求解器以字典序比較是否保留前方配件，可能因此少裝幾件。UI 使用 `objective: priority`；擴格依賴仍可先安裝較後方的擴格配件。達時間／節點上限不宣稱已找到最優解。
- 即時排放預設開啟，新增、移除、排序、擴格方向或設定變更後自動執行；180ms 合併連續操作，終止舊 Worker 並以 request ID／裝備檢查拒絕舊結果。可暫停即時排放改用手動；一般情況不顯示多餘的重新排放鈕，受限搜尋可延長。
- 960px 以上維持三欄；平板改兩欄與下方圖，手機改直向並提供三欄位跳轉。名稱維持 15px，格形縮小僅供辨識。縮圖沿用既有本機資產，格形仍以 JSON 座標繪製。

驗證：沿用檢查器加入獨立小面板全列舉對照優先策略、前方大件與後方多件的取捨、擴格依賴、同款多份排序不改 ID／方向、基礎面板與旋轉獨立、品質色及來源排序。瀏覽器核對截圖同款六項配置、拖曳第三項至第一、箭頭排序、連續加入自動排放、移除擴格縮回、即時暫停／恢復、四分類及固定重武器面板；1280px、960px、390px、320px 無整頁水平溢出，無重複 ID 或 JavaScript 錯誤。旋轉選項以解鎖等效等級保存於舊 `playerLevel` 欄位，不代表輸入玩家精確等級；配置匯出仍為 schema 2，新增 priority 目標與基礎面板階段資訊。收集資料與備份格式不改動。

### 擴格配裝與閱讀調整（2026-10-24）

## 資料範圍與限制

- 檔名的 v1.6 是舊資料表版本，不等同遊戲版本。Wiki 清單為本次查核的固定修訂，不會隨開站即時更新；遊戲內效果仍待實機核對。
- 新圖鑑共 842 筆，其中 840 筆來自 Wiki，兩筆為舊表保留。同名項目跨裝備分開記錄；不能將圖鑑筆數當作獎盃需求總數。
- 中文由 AI 輔助翻譯並修飾，角色與武器中文名稱也屬暫譯，尚未與遊戲內用詞核對。英文原文與數字始終保留。
- 效果分類使用英文關鍵字多標籤，僅供查找，不是實測推薦；例如裝填速度不會自動被分類為移動速度。
- 數值、負號與上下界順序依來源保留，不自行交換看似反向的 Min/Max。描述與數值矛盾、疑似誤植或殘文也不憑空修補。
- Wiki 未列的 Turbocharge 不沿用舊表數值；空白不補寫效果，`[Redacted]` 保留隱去狀態。
- 舊 Build 與參考輔助分頁不納入配件清單；原表中的失效引用不會當作正式推薦匯入。
- 配件圖示來自使用者提供的工作簿；首頁分類線圖為本站自繪。格形以資料產生向量六角格，不複製第三方求解器。

## 收集紀錄與備份

紀錄存在瀏覽器 `localStorage`，不會傳送至伺服器。**網址的主機或連接埠不同，就有不同的儲存空間**；換瀏覽器、裝置、網站網址或清除網站資料前，請先匯出備份。

每個穩定 ID 由裝備 ID 與英文配件名稱產生，不依列號、排序或中文翻譯變動。未來英文改名時仍需建立 ID 遷移對照，不能直接把原紀錄丟棄。

備份格式為 `appId: mycopunk-checklist`、`schemaVersion: 1`，`records` 依 ID 儲存 `collected`、`tracked`、`note` 與 `updatedAt`。支援 10 MB 以下的 JSON 備份；為相容舊版，仍接收每筆上限 5,000 字的舊筆記並隨匯出保留。

匯入會先顯示新增、更新、保留本機與未對應筆數：

1. 同一 ID 保留 `updatedAt` 較新的整筆紀錄，包含明確的「未取得」狀態；時間相同時保留本機版本。
2. 備份未包含的本機紀錄不刪除。未對應目前圖鑑的 ID 仍會保留並隨備份匯出。
3. 寫入前先保存原始儲存文字；可在「資料說明 → 匯入前備份」下載。這是最近一次匯入前的單份備份，再次匯入會替換它。
4. 原有資料若毀損或版本不支援，暫停修改並保留原始文字，可下載調查或用有效備份修復。
5. 儲存不可用時會顯示提示，本次勾選與追蹤暫存在記憶體，請在離開前匯出。備份匯入若無法先保存原始資料，則停止覆寫。
